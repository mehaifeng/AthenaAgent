# Athena 使用文档（中文）

## 1. 本文档范围
本指南只聚焦四件事：
- Chat 首页能做什么。
- 设置页每类配置项是什么意思、怎么配。
- 主动消息（定时触发到聊天页）怎么配置和使用。
- LLM 如何利用知识库主动记忆和学习用户偏好，并保持长期上下文连贯。

## 2. Chat 首页功能
### 2.1 核心交互
- 输入框发送：按 `Enter` 或点击发送按钮。
- 流式回复：助手边生成边显示，支持中途“停止回复”。
- 新建对话：一键清空当前会话并开始新线程。
- 消息级操作：支持复制、编辑用户消息、对助手回复重新生成、删除消息。

### 2.2 上下文可控能力
- 顶部显示上下文 Token 使用量，帮助判断会话是否过长。
- 达到阈值时可自动压缩历史上下文（保留摘要 + 最近轮次），降低长对话漂移。
- 草稿恢复：应用重启后可恢复未完成主对话，减少中断损失。

## 3. 设置页怎么理解与配置
设置页为自动保存，不需要单独点击保存。

### 3.1 外观与交互偏好
- 主题（Theme）：仅影响界面外观。
- 语言（Language）：影响界面文案与 About 页文档跳转语言。
- 跳过确认（重新生成/编辑）：开启后操作更快，但误操作回退成本更高。

建议：
- 初期先不要跳过确认，熟悉流程后再开启。

### 3.2 主模型（Primary AI）
- Provider / Endpoint / API Key：模型服务连接三件套。
- Model：主对话模型。
- Temperature：创造性与稳定性的平衡。
- MaxTokens：单次回复上限。
- EnableFunctionCalling：是否允许模型调用工具能力。

建议（通用）：
- 生产/严谨任务：`Temperature` 0.2~0.7。
- 先点“连接测试”通过，再开始正式对话。
- 主模型优先选你最稳定、响应质量最一致的模型。

### 3.3 辅助模型（后台/嵌入）
- Secondary AI：用于摘要等后台任务，可与主模型分离。
- Embedding：用于知识库向量检索语义匹配。

建议：
- Secondary 可选更轻量、更低成本模型。
- Embedding 模型要稳定，不建议频繁切换，否则历史向量一致性会受影响。

### 3.4 记忆与上下文压缩
- MaxContextTokens：会话最大上下文预算。
- CompressionThreshold：超过该阈值时触发压缩。
- AutoCompress：是否自动压缩。
- 压缩预览/执行压缩/撤销摘要：用于观察和控制上下文摘要状态。

建议（先稳后优）：
- 长会话默认开启 `AutoCompress`。
- `CompressionThreshold` 建议设为 `MaxContextTokens` 的 40%~70%。
- 重要项目对话中，定期检查压缩摘要是否保留关键约束（目标、边界、术语、验收标准）。

## 4. 主动消息（Proactive Message）如何使用
主动消息由系统调度机制触发：到达触发时间后，系统会自动切到 Chat，并注入一条隐藏触发消息，驱动助手先说话。

### 4.1 创建方式
你可以通过两种方式创建主动消息：
1. 手动创建：进入 `Tasks` 页面创建任务，填写触发时间、意图（Intent）、循环方式，并将任务类型设为 `Foreground / Proactive`。
2. 对话委托创建：在聊天中直接告诉 LLM 你的提醒目标和时间安排，LLM 会通过系统内置机制为你建立对应的主动消息任务。

### 4.2 Intent 写法模板（推荐）
把 Intent 写成“可执行提示”，避免空泛提醒：
- 目标：要推进什么。
- 上下文：基于哪个项目/会话状态。
- 产出：希望助手给出什么格式结果。

示例：
- “每天 09:30 检查 Athena 文档完善进度，输出：昨日变化、今日风险、下一步 3 条动作。”

### 4.3 使用注意
- Proactive 适合需要你看到并互动的提醒。
- Background 适合静默任务，不会主动打断聊天界面。

## 5. LLM 如何利用知识库主动记忆学习用户

### 5.1 主动记忆机制
- LLM 会结合当前会话与知识库内容，持续归纳你的常用偏好，例如表达风格、输出结构、决策边界和任务优先级。
- 当会话较长时，系统通过上下文压缩保留核心摘要，让“用户偏好 + 项目约束”继续留在有效上下文里。
- 通过历史草稿恢复与连续对话，LLM 能在多次会话中逐步形成更稳定的协作画像。

### 5.2 知识库中的“长期记忆”与会话中的“短期记忆”
- 知识库承载长期稳定信息：术语、规范、历史决策、架构边界。
- 当前会话承载短期变化信息：当日进展、临时策略、阶段性风险。
- LLM 会在回答时融合两类记忆：先参考长期稳定约束，再吸收最新对话变化。

### 5.3 你需要做的最小动作
- 不需要每轮都重复完整约束，只要在目标发生变化时补充新约束即可。
- 如果你觉得回答开始偏离，只需一句话指出“继续按既有知识库规范和当前目标收敛”，LLM 会自动回收上下文焦点。
- 定期把新形成且稳定的规则沉淀进知识库，LLM 后续会更主动复用这些记忆。

## 6. 一套可复用的高质量提问模板
你可以反复复用以下结构：

```text
目标：
约束：
当前状态：
请先输出：
完成标准：
```

示例：
```text
目标：把日志筛选与导出流程改到可直接上线。
约束：不改现有服务接口；保持现有 UI 风格；必须可回归。
当前状态：级别筛选映射已修复，但还要补导出交互和列表可用性。
请先输出：最小改动方案 + 变更文件清单，再实施。
完成标准：编译通过；核心交互手测通过；给出风险点。
```

这类结构化输入会显著提升回答稳定性与连续多轮一致性。
