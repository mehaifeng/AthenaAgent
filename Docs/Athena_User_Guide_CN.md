# Athena 使用文档（中文）

## 1. 本文档范围
本指南聚焦以下几件事：
- 三栏工作区与主对话能做什么（含附件、截图、子代理）。
- 应用设置与供应商模型分别管理什么。
- Skills、MCP、语音、图像、搜索和文档解析如何启用与管理。
- 主动消息（定时触发到聊天页）怎么配置和使用。
- 知识库页面怎么用，以及 LLM 如何借助知识库主动记忆和学习用户偏好。

## 2. 三栏工作区与主对话

![三栏工作区](images/MainShell.png)

左栏负责工作区与会话树，中栏永久显示当前主对话，右栏承载工作区文件、工作台和紧凑日志。会话可直接在树中置顶、重命名、分支、导出、搜索和删除。

### 2.1 核心交互
- 输入框发送：按 `Enter` 或点击发送按钮。
- 流式回复：助手边生成边显示，支持中途"停止回复"。
- 新建对话：一键清空当前会话并开始新线程。
- 消息级操作：支持复制、编辑用户消息、对助手回复重新生成、删除消息。
- 消息带发送时间前缀，便于回溯时间线。

### 2.2 附件与文档解析
- 通过输入框左侧的加号按钮添加本地文件附件。
- 支持 MinerU 文档解析：可从 PDF 等附件中提取大纲与正文内容，供助手引用。
- 内置截图按钮：可选择截图时隐藏或保留 Athena 窗口。

### 2.3 工具调用与子代理
- 工具调用过程有可视化状态卡片（如截图中的 `dispatch_subagents`），执行中与执行完毕均有提示，中间 JSON 消息保留在上下文中但不在界面显示。
- 子代理：助手可通过 `dispatch_subagents` 并行派发多个子任务（文件操作、联网搜索、浏览器任务等），各子代理独立运行，结果汇总回主对话；运行状态可在"猫头鹰之城"面板中查看。
- 浏览器任务：`run_browser_task` 由视觉引导的浏览器智能体执行多步网页操作。

### 2.4 上下文可控能力
- 顶部显示上下文 Token 使用量（如 `9832 / 1280000 tokens`），帮助判断会话是否过长。
- 达到阈值时可自动压缩历史上下文（保留摘要 + 最近轮次），降低长对话漂移。
- 草稿恢复：应用重启后可恢复未完成主对话，减少中断损失。

## 3. 应用设置与供应商模型

![应用设置窗口](images/AppSettingsWindow.png)

设置页为自动保存，不需要单独点击保存。

### 3.1 外观与交互偏好
- 显示主题：仅影响界面外观。
- 语言设置：影响界面文案与 About 页文档跳转语言。
- 跳过回滚确认（重新生成/编辑）：开启后操作更快，但误操作回退成本更高。

建议：
- 初期先不要跳过确认，熟悉流程后再开启。

### 3.2 供应商模型
- 从启动器打开“供应商模型”，管理 OpenAI 兼容供应商、端点、API 密钥和已发现模型。
- 主对话、标题生成、上下文压缩、自动审批、Embedding、浏览器、子代理、知识整理和图像识别可分别选择模型。
- 如有兼容需求，可保留一套独立 Embedding 连接。

建议（通用）：
- 刷新供应商模型列表可同时验证端点与凭据。
- 主模型优先选你最稳定、响应质量最一致的模型。

### 3.3 运行、审批与诊断
应用设置负责上下文限制、自动压缩、工作区知识预算、子代理并发、工具审批模式与放行清单，以及浏览器运行时和 Browser Agent 诊断。

建议：
- Embedding 模型要稳定，不建议频繁切换，否则历史向量一致性会受影响。

### 3.4 记忆与上下文压缩
- MaxContextTokens：会话最大上下文预算。
- CompressionThreshold：超过该阈值时触发压缩。
- AutoCompress：是否自动压缩。

建议（先稳后优）：
- 长会话默认开启 `AutoCompress`。
- `CompressionThreshold` 建议设为 `MaxContextTokens` 的 40%~70%。

## 4. Skills 与连接器

![Skills 与连接器窗口](images/SkillsConnectorsWindow.png)

独立的 Skills 与连接器窗口包含六个持久页面：Skills、MCP、语音、图像生成、Web Search 和文档解析。切换页面不会重建页面 VM 或丢失正在编辑的状态，各项配置会自动保存。

- **语音**：打开语音开关后，可配置服务商、API 端点、API 密钥、模型名和音色；可单独设置是否自动播放，并使用“诊断”检查配置是否可用。
- **图像生成**：打开后，助手可通过 `generate_image` 生成图片；填写对应的 API 端点、API 密钥和模型名即可。
- **网络搜索**：打开后，助手可使用 `web_search` 查询实时信息；按所选服务商填写端点与凭据。

建议：只开启实际会用到的扩展；密钥仅填写在本机配置中，不要发送到普通对话或知识库文件。

## 5. 技能（Skills）

技能让 Athena 在特定类型的任务中遵循可复用的专业工作流。

1. 打开“启用技能”总开关。
2. 使用“导入 ZIP”或“导入文件夹”导入一个技能；也可点击“打开文件夹”直接管理本机技能目录。
3. 点击“刷新”重新扫描；展开某项可查看来源、兼容性和说明。
4. 用每个技能右侧的开关暂时停用它；确认不再需要时再点击删除。

技能应以单个、包含 `SKILL.md` 的技能文件夹或 ZIP 包导入。导入后，在对话中直接提出匹配的任务即可由 Athena 选择使用。

## 6. MCP 服务器

MCP（Model Context Protocol）让 Athena 连接外部服务器，并按需使用其提供的工具和数据。

1. 打开“启用 MCP”总开关。
2. 点击“添加服务器”配置一个本地命令型或远程 HTTP/SSE MCP 服务器；也可粘贴 Claude Desktop 格式的 JSON 后点击“导入”。
3. 连接成功后，列表会显示已发现的工具数；展开服务器可查看详情。
4. 使用每项右侧开关控制该服务器是否可用；垃圾桶按钮会移除服务器并停止其本地进程。

仅添加可信服务器。MCP 服务器可能访问本地文件、网络或第三方服务；涉及外部工具调用时，请在审批提示中核对实际操作。

## 7. 主动消息（Proactive Message）如何使用
主动消息由系统调度机制触发：到达触发时间后，系统会激活当前主对话、闪烁托盘提示，并注入任务意图，驱动助手先说话。

### 7.1 创建方式
你可以通过两种方式创建主动消息：
1. 手动创建：进入"计划"页面创建任务，填写触发时间、意图（Intent）、循环方式，并将任务类型设为 `Foreground / Proactive`。
2. 对话委托创建：在聊天中直接告诉 LLM 你的提醒目标和时间安排，LLM 会通过系统内置机制为你建立对应的主动消息任务。

### 7.2 Intent 写法模板（推荐）
把 Intent 写成"可执行提示"，避免空泛提醒：
- 目标：要推进什么。
- 上下文：基于哪个项目/会话状态。
- 产出：希望助手给出什么格式结果。

示例：
- "每天 09:30 检查 Athena 文档完善进度，输出：昨日变化、今日风险、下一步 3 条动作。"

### 7.3 使用注意
- Proactive 适合需要你看到并互动的提醒。
- Background 适合静默任务，不会主动打断聊天界面。

## 8. 知识库与长期记忆

![知识库窗口](images/KnowledgeBaseWindow.png)

### 8.1 知识库页面
- 左侧为目录结构，可直接新建文件夹和 Markdown 文件，组织长期记忆（如 `user_preferences`、`user_profiles`）。
- 右侧可查看和编辑 Markdown 内容，顶部显示文件真实路径。
- 工具栏提供刷新、导入、导出、删除、知识整理和向量索引全量重建操作。
- 知识库内容会同步写入向量数据库，写入即可被语义检索命中。

### 8.2 主动记忆机制
- LLM 会结合当前会话与知识库内容，持续归纳你的常用偏好，例如表达风格、输出结构、决策边界和任务优先级，并通过 `create_new_memory` / `recall_from_memory` 主动读写知识库。
- 当会话较长时，系统通过上下文压缩保留核心摘要，让"用户偏好 + 项目约束"继续留在有效上下文里。
- 通过历史草稿恢复与连续对话，LLM 能在多次会话中逐步形成更稳定的协作画像。

### 8.3 知识库中的"长期记忆"与会话中的"短期记忆"
- 知识库承载长期稳定信息：术语、规范、历史决策、架构边界。
- 当前会话承载短期变化信息：当日进展、临时策略、阶段性风险。
- LLM 会在回答时融合两类记忆：先参考长期稳定约束，再吸收最新对话变化。

### 8.4 你需要做的最小动作
- 不需要每轮都重复完整约束，只要在目标发生变化时补充新约束即可。
- 如果你觉得回答开始偏离，只需一句话指出"继续按既有知识库规范和当前目标收敛"，LLM 会自动回收上下文焦点。
- 定期把新形成且稳定的规则沉淀进知识库，LLM 后续会更主动复用这些记忆。

## 9. 一套可复用的高质量提问模板
你可以反复复用以下结构：

```text
目标：
约束：
当前状态：
请先输出：
完成标准：
```

示例：
```text
目标：把日志筛选与导出流程改到可直接上线。
约束：不改现有服务接口；保持现有 UI 风格；必须可回归。
当前状态：级别筛选映射已修复，但还要补导出交互和列表可用性。
请先输出：最小改动方案 + 变更文件清单，再实施。
完成标准：编译通过；核心交互手测通过；给出风险点。
```

这类结构化输入会显著提升回答稳定性与连续多轮一致性。
