# 游戏模式的 /goal 目标（分三段）

> 配合 `Docs/GameMode_Design_CN.md` 使用，2026-10-11。每段在一个新会话里设一个 `/goal`，段与段之间由人验收。

## 为什么分三段

- 设计稿自己的验收标准需要真人：M0 要给不懂技术的人看，M1 要看他们自己选哪种模式。`/goal` 的评估模型只读对话记录，判断不了这些。
- 一口气跑几百轮容易跑偏，最后的 PR 也没法审。
- 每段结束后，可以根据结果调整下一段的条件。

## 使用前：确认评估器能用

`/goal` 每轮结束时，由"小模型"（`ANTHROPIC_DEFAULT_HAIKU_MODEL`）读对话记录判断条件是否满足。如果用户级设置把它映射到了会话所连供应商上不存在的模型，评估就会失败，目标根本跑不起来。

修法：在本项目的 `.claude/settings.local.json`（已被 git 忽略）的 `env` 里，把它覆盖成会话供应商上存在的模型。长时间运行中会派出子代理，`CLAUDE_CODE_SUBAGENT_MODEL` 同理。改完在新会话里先跑一句 `/goal 回复 OK 两个字`，看到目标达成的记录，评估器就是通的。

## 用法

- 每段开一个新会话，切到自动模式，粘贴对应的整段文字。目标一设好就开始干活，不用另发消息。
- 运行中输入 `/goal`（不带参数）看进度：轮数、耗时、token 花费；中途停下用 `/goal clear`。
- 段间验收：
  - M0 之后，按演示说明给两三个不懂技术的人看；
  - M1 之后，按手动验收清单走一遍；
  - M2 之后，看美术审查记录，再观察一周的使用情况。
- 每段条件都在 4,000 字符以内（`/goal` 的上限）。M1、M2 会推送分支并开 PR；不想让它碰远端，删掉那半句即可。

## M0：城邦原型 + 真实会话回放

```text
/goal 实现游戏模式 M0（城邦原型 + 真实会话回放），直到下面的"完成标准"全部满足，并在最后一轮贴出证据。

开始前：
- 读 CLAUDE.md、Docs/GameMode_Design_CN.md 全文和 Artwork/Polis/sample/ 的代码。main 上没有设计稿时，以 docs/game-mode-design 分支为基础。新建分支 feature/game-mode-m0，所有改动都在这个分支上小步提交。
- 建立并持续维护 Docs/GameMode_Progress_CN.md：本阶段清单、每项的验证证据（命令与关键输出）、做过的决定、阻塞。上下文被压缩后先读它再继续。
- 每轮结尾用一行汇报：第几轮、清单完成了几项。

范围（M0 不接入应用、不调用任何模型）：
1. 从 logs.db 统计真实的工具调用节奏：每回合调用数、并行突发大小、调用间隔、等模型的时长。只输出聚合数字，写进进度文件。
2. 导出夹具：把一个真实文件夹（就用本仓库）扫描成城邦快照，把一段真实会话转成回放事件（工具类别、工作区相对路径、时间）。扫描、建筑汇总、布局账本、回放转换写成 C# 纯函数，在 Athena.Archive.Tests 里测试；导出入口可以是一个小控制台工程（参照 Athena.Archive.Tests 用 <Compile Include> 引入源码的做法）。
3. 网页原型放在 Tools/GameMode/ 下，从 Artwork/Polis/sample/ 起步（程序化神庙、器物、植物、黑白调色、点缀色遮罩、光晕和运动自检都已经有了）。引擎以打样用的 three.js 为基线，要换就把理由写进进度文件；资源离线打包，不引用 CDN。加载夹具并回放：按 5.1 的映射用认得出来的程序化建筑（至少柱廊书库、民居、作坊三种，不用纯方块）、雅典娜（周身有光）、玩家（点哪走哪）、旁白模板。
4. 编排器实现 6.2 的全部节奏规则：工具执行不等动画、收尾有上限、同地点合并、移动必须完成、落后超过阈值就瞬移、等模型时沉思。
5. 写 M0 演示说明：怎么启动回放，给不懂技术的人看时注意什么。

约束：
- 不改应用的运行时行为，不引入新的 NuGet 包。
- 由真实数据导出的夹具和截图不进仓库，放进被 .gitignore 忽略的目录；测试只用合成夹具；回放事件里不含消息正文。
- 美术全部由代码生成，不下载第三方美术素材；人物不做 3D 近景。
- 按 CLAUDE.md 的方式跑测试，不用 dotnet run 跑测试。截图照 Artwork/Polis/sample/shoot.mjs 的做法用应用自带的 Playwright 驱动，不要用 chrome --headless --screenshot（在 macOS 上会挂死）。

完成标准：
a. 解决方案构建成功，Athena.Archive.Tests 全部通过，新增的 C# 纯函数都有断言。
b. 编排器的 Node 单测全部通过，6.2 的每条规则至少一条用例。
c. Playwright 冒烟测试在 Chromium 和 WebKit 下都通过：加载合成夹具后页面报告"就绪"，没有控制台错误，画面非空。
d. 运动自检：镜头按脚本逐帧移动时，光晕等屏幕空间效果与当帧真实投影的最大偏差不超过 0.5 像素，贴出数值。
e. 用真实夹具回放一次，截 5 张不同时刻的图（存进被忽略的目录），逐张看过，在进度文件里写下看到的问题和处理结果。
f. 进度文件里有节奏统计和引擎选择理由，M0 清单全部勾选并附证据；本阶段改动已全部提交（不属于本阶段的未跟踪文件不要动）。
g. 最后一轮重新跑 a–d 的命令，贴出结果，并打印进度清单。

如果遇到只能由我决定的问题，写进进度文件的"阻塞"一节并在回复里列出，然后停下——这也算本目标结束。满 40 轮仍未完成时同样停下，写清剩余事项。
```

## M1：接入应用

```text

开始前：

- 先查前置改动是否已经在 main 上（例如工作台文件监听的 Error 处理），已有的直接复用。

范围（设计稿第 9–12 节、第 14 节 M1 行）：
1. 前置：把 FileSystemService.GeneratedDirectoryNames 提出来共用；把工作区文件监听提成服务，工作台和游戏共用，出错时整城重扫；加"重新定位工作区文件夹"入口（只改 DirectoryPath，Id 不变）。
2. 中间区域加游戏/对话模式切换：按钮放在对话标题栏，模式存进 MainLayoutSettings；游戏视图替换消息列表那一行，输入框保留；进入游戏时收起宠物；NativeWebView 惰性创建，页面由 OfficePreviewHost 新增的路由提供，前端离线打包。
3. 城邦：C# 扫描（有界、可取消、后台线程）、建筑汇总、布局账本；会话树是唯一的选择来源，按 9.2 处理同工作区、跨工作区和全局对话的切换。
4. 存档与重启（第 10 节）：存进 AthenaData/Workspaces/<id>/game/，原子写入、按记录隔离损坏、带 schema 版本；先按快照显示，再核对差异。
5. 外部改动同步（第 11 节）：增量更新、区分雅典娜与外部改动、批量合并、离线差异报告与改名找回、文件夹丢失时的雾与重新定位。

7. 安全边界（12.4）：网页意图是封闭集合，在 C# 逐条校验；网页没有"批准"意图；文字画在 canvas 上。
8. 失败处理（12.5）：四处检测，任何一处都在游戏区显示原因和"回到对话"按钮并记 Warning；Linux 同样处理。不可见时暂停渲染，空闲降帧。

约束：
- 第 15 节的待定问题按设计稿建议的默认做法处理，并记进进度文件；但第 5 条（启动时恢复上次选中的会话）不要做，留给我决定。
- 美术沿用 M0 的程序化资产，不下载第三方素材，人物不做 3D 近景；屏幕空间效果用当帧相机矩阵投影（设计稿 12.2）。遵守 CLAUDE.md 的评审规则。

完成标准：
a. 解决方案构建成功；Athena.Archive.Tests 全部通过；无头测试套件（Scripts/run-headless-tests.sh）全部通过、退出码 0。
b. 新增断言覆盖：布局账本稳定（删一个文件夹不挪动其他建筑）、存档损坏隔离与迁移、离线差异与改名找回、雅典娜与外部改动的归属、意图校验（越界路径和"批准"都被拒绝）、模式切换与失败提示（无头测试，不实例化 WebView）。
c. Node 单测、Playwright 冒烟测试（Chromium、WebKit）和运动自检全部通过。
d. 写一份手动验收清单留给我：进入游戏、切换工作区、重启后恢复、在应用外增删文件夹、失败提示。
e. 进度文件的 M1 清单全部勾选并附证据；本阶段改动已全部提交（不属于本阶段的未跟踪文件不要动）；推送分支，开一个以 main 为目标的 PR，不要合并。
f. 最后一轮重新跑 a–c 的命令，贴出结果，并打印进度清单。
```

## M2：积累系统、群岛海图、程序化美术库

```text

2. 橄榄林：每完成一次委托长一棵树，从会话归档推导、不另存；点树 = 选中该会话，走会话树的同一条路径。

约束：设计稿第 15 节第 5 条（启动时恢复上次选中的会话）不要做，留给我决定；美术全部由代码生成，不下载第三方素材；屏幕空间效果用当帧相机矩阵投影；遵守 CLAUDE.md 的评审规则。
```
