# 游戏模式设计：雅典娜的城邦

> 状态：设计稿 v3，2026-10-11（v1：2026-10-10；v2 加入美术打样的结论，见 12.8；v3 记下 M1 接入时定下的数值与被实测推翻的部分，见各节"M1："标注）。
> M0（浏览器里的原型）与 M1（接入应用）已经落地，实际行为写在 `CLAUDE.md` / `AGENTS.md` 的 "Game Mode" 一节，以那里为准；
> 进度、决定与证据见 `Docs/GameMode_Progress_CN.md`，手动验收见 `Docs/GameMode_M1_Acceptance_CN.md`。本文仍是方向与约束；M2（美术与积累）尚未开始。

## 0. 一页摘要

在中间区域加一个游戏模式，与对话模式**切换**使用：工作区变成一座 2.5D 写实风格的古希腊城邦，雅典娜（Agent）在城里干活，你（玩家）住在城里。目标是让**非技术用户**愿意留在游戏模式里，而不是退回对话框。对话模式保留它的细节优势，留给技术型用户。两种模式是同一个会话的两种呈现，随时切换，不丢任何东西。

游戏模式要胜过对话框，靠三件事：

1. **积累**：对话是一条不断往上滚走的流水，城邦却一直摆在那里，成果和历史都看得见、摸得着。
2. **看得懂**：雅典娜在你的"文件地图"上走动，用人话说明她在做什么。
3. **知道还能让她做什么**：能力是城里的建筑和居民，广场上有委托板。

## 1. 已定的方向

以下方向已于 2026-10-10 确定（美术与人物近景两行于 2026-10-11 确定），改动前需先确认：

| 项 | 决定 |
|---|---|
| 主角 | 玩家（用户本人）；看和玩并重 |
| 目标用户 | 非技术用户；技术型用户继续用对话模式 |
| 视角与风格 | 2.5D，写实古希腊，黑白灰，允许少量点缀色（《辛德勒的名单》红衣女孩式） |
| 与对话的关系 | 切换，不同屏 |
| Linux | 照常支持；跑不起来或出错时明确告诉用户，不静默降级 |
| 美术 | 全部新做，由代码生成（程序化资产库 + 截图审查 + 运动自检），保留资产清单接口，任何一件都能单独换成外部模型。不复用子代理猫头鹰素材（它的 V2 帧是逐帧生成的，有解剖错误，比如调用工具的帧多出一对翅膀）。打样见 `Artwork/Polis/sample/` |
| 人物近景 | 3D 人物只出现在游戏视距；对话等特写用 2D 半身像（SVG 线描），不做 3D 人物近景 |
| 雅典娜形象 | 真身出现，不披甲、不持兵器，穿一件素朴淡雅的古希腊女装 |
| 实现载体 | 网页，嵌在 `NativeWebView` 里，复用 Office 预览的 WebView 基础设施 |

## 2. 核心概念：雅典娜为你建的记忆宫殿

"记忆宫殿"（位置记忆法）是希腊人发明的，相传出自诗人西摩尼德斯：把要记的东西放进想象中的建筑里，因为人记地点远比记清单牢。把工作区变成城邦，就是给文件建一座记忆宫殿。所以这个世界不只是好看，它本身就能帮非技术用户找到东西。前提是城市布局保持稳定（见 5.2）。

## 3. 设计原则

1. **城邦里的一切都是真的。** 每座建筑、每件物品都对应一个真实的文件夹或文件；每件藏品都是一次真实的产出。没有虚构的资源、货币或任务。游戏化产品最常见的失败，就是奖励和真实价值脱钩。
2. **最快的路和对话一样快。** 在任何地方都能直接跟雅典娜说话，不必先走到某座建筑。地点和物品提供上下文和灵感，不是关卡。游戏只要比对话慢，非技术用户就会回去用对话。
3. **雅典娜从不等动画。** 工具执行永远不等画面。动画落后时，她化作一道光瞬移过去。神本来就能瞬移，所以"落后就快进"是故事的一部分，而不是穿帮。
4. **颜色只有一个意思："轮到你了"。** 见第 8 节。
5. **只积累，不消耗。** 不设货币、体力和连续签到惩罚。留住人的，是这座城邦越来越像"你的"。

## 4. 角色

### 4.1 你：城邦的主人

- 操作方式是"点哪走哪"。不玩游戏的人最熟悉这种操作，而且不占用键盘，不会跟输入框抢焦点。镜头可以缩放、平移。
- 动作只有几种：走、看、拿起、交给雅典娜、摆放、收下或退回。每个动作都对应应用里已有的功能（见 7.1），不发明新能力。

### 4.2 雅典娜：Agent

- **真身出现，不披甲、不持兵器。** 她穿一件素朴淡雅的佩普洛斯（peplos，古希腊女性的长袍式外衣；泛雅典娜节上献给雅典娜神像的就是一件佩普洛斯），可以搭一条简单的披肩。
- **让人认出她是神的是光，不是装备。** 她周身有一层柔和的光，干活时更亮。这和第 8 节"光属于雅典娜"是同一条规则。去掉甲胄之后，这层光是她唯一的神性标记，不能省。
- 她比常人略高，动作安静从容。她是唯一会干活的角色，玩家所说的"看"，就是看她。

### 4.3 黄金侍女：子代理

- 《伊利亚特》里，赫菲斯托斯的黄金侍女会思考、会说话，常被称作神话里最早的 AI。调用 `dispatch_subagents` 时，雅典娜唤出她们分头去各处；任务结束后，侍女回到她身边，然后消散。
- 在游戏模式里，她们取代猫头鹰村。对话模式里的猫头鹰村不受影响。

## 5. 世界：工作区怎么变成城邦

### 5.1 映射

| 工作区 | 城邦 |
|---|---|
| 工作区 | 一座城邦（按工作区 `Id` 识别，见 9.1） |
| 根目录 | 整座城，中心是广场 |
| 顶层文件夹 | 一座建筑。类型取决于里面主要放什么：文档→柱廊书库，图片→雕塑园，表格→金库或市集，代码→作坊，压缩包→仓库，混杂→民居 |
| 文件数量 | 建筑体量（取对数，免得一个大文件夹压垮全城） |
| 最近修改时间 | 建筑状态：常用的有人走动、有灯光；很久没动的爬满常春藤，慢慢变成废墟 |
| 单个文件 | 平时不单独出现；只有雅典娜碰过的、刚产出的、你打开或摆放过的，才变成可见的物品 |
| 工作区以外的路径 | 城外：雅典娜出城门，办完事再回来 |

### 5.2 布局

- **用希波达摩斯式棋盘格布局**（比雷埃夫斯港就是这样规划的）。中心是广场，公共建筑围着广场，文件夹对应的建筑按街区向外排开。这种布局既符合历史，也最容易保持稳定。
- **用布局账本记录地块**：哪个文件夹占哪块地，由账本记录并存档（见第 10 节）。
  - 新文件夹在城市边缘占一块新地；
  - 被删的文件夹留下空地或废墟；
  - 网格永不收缩，已有建筑永不挪位。

  没有账本做不到这一点：如果纯按路径哈希排列，删掉一个文件夹就可能让别的建筑换位置，空间记忆随之作废。
- **控制规模**：
  - 扫描时跳过构建和依赖目录，复用 `FileSystemService.GeneratedDirectoryNames`（目前是私有字段，需要提出来共用）；
  - 扫描的条目数设上限，超出部分标成"未完全测绘"；
  - 顶层文件夹太多时，只给最近常用的盖独立建筑，其余并入市集里成排的摊位（阈值待定）。

### 5.3 公共建筑：能力

能力做成公共建筑，非技术用户在城里逛一圈就能发现：

| 建筑 | 对应能力 |
|---|---|
| 广场与委托板 | 发起新委托、查看建议（见 7.3） |
| 图书馆 | 记忆（知识库）：能看到雅典娜记住了什么 |
| 港口 | 网页搜索、网页抓取、浏览器任务 |
| 锻炉 | 终端命令 |
| 日晷与传令官 | 定时任务及其结果 |
| 神庙 | 每日神谕（定时任务的仪式入口，见 7.3） |
| 彩绘柱廊 | 陈列成果 |
| 橄榄林 | 历史：已完成的委托 |

### 5.4 第一次进入

第一次进入某个工作区时，城邦"奠基"：先播放一段简短的俯瞰揭幕，旁白是"这是你的城邦，每座建筑都是你的一个文件夹"；随后雅典娜根据委托板给出第一条建议。之后每次进入都直接从存档恢复，不再播放揭幕。

## 6. 雅典娜的动作

### 6.1 映射

雅典娜的动作按工具类别归成十来种。每一种都意味着一套要做的动画，所以种类要克制。

工具到类别的映射以 `Services/SubAgents/SubAgentZones.cs` 为起点补全。这张表现在登记了 24 个工具，没登记的一律归入工坊。游戏和猫头鹰村共用这张表，新工具登记一次，两边就都有动作。

| Agent 在做的事 | 雅典娜的动作 | 旁白举例 |
|---|---|---|
| 读文件、列目录、搜索 | 走进对应的建筑，展开卷轴 | 「我去书库翻翻《合同》」 |
| 写入、修改、生成 Office 文档 | 在卷轴或石板上书写，建筑搭起脚手架 | 「我在誊写新的报告」 |
| 执行终端命令 | 在锻炉前锻打 | 「炉火点上了」 |
| 网页搜索、抓取、浏览器任务 | 从港口放船出海，船回来卸货 | 「船出海打听消息去了」 |
| 推理、等待模型输出 | 原地沉思，身上的光一明一暗 | （不说话） |
| 派发子代理 | 唤出黄金侍女，让她们分头出发 | 「我叫上了三位侍女」 |
| 读写记忆 | 去图书馆放入或取出卷轴 | 「这件事我记下了」 |
| 等待审批 | 停在门槛前，手中石板的封印是红色的 | 「这一步需要你点头」 |
| 失败、重试 | 光暗下去，天边起风 | 「这条路走不通，我换一条」 |
| 交付结果 | 走到你面前，递上成果 | 「做好了，你看看」 |

### 6.2 节奏

工具调用是一阵一阵的：可能一秒内并行跑完 4 个只读调用，然后几十秒都在等模型输出。

猫头鹰村已经验证过的规则全部沿用（见 `Artwork/SubAgents/README.md`）：

- 工具执行永远不等动画；
- 动画收尾的时间有上限；
- 同一地点的连续动作合并成一次；
- 闲逛打断不了赶路，每次移动都要完成。

新增两条：

- **画面落后超过阈值就瞬移**，不排队。阈值从 3 秒起调。
- **等模型的时间不能出现空白。** 推理内容的增长驱动"沉思"状态。

真实节奏要用数据来定。归档里的 `ToolCallEntry` 只有顺序，没有时间戳；时间分布要从 `AthenaData/Logs/logs.db` 里取，这是 M0 的第一件事。

### 6.3 旁白

- 旁白按工具类别套模板生成，在本地完成，零成本，做法和宠物台词库一样（写在 locale 文件里，用 `|` 分隔多个变体）。文件用显示名（「《合同》」），不用路径。
- 工具参数、推理原文、token 用量都不展示，留给对话模式。

## 7. 玩法循环

### 7.1 委托（几分钟）：说 → 看 → 定 → 收 → 评

- **说**：沿用对话模式的输入框，游戏模式下只换皮肤。发消息只走一条代码路径，上下文管理、附件、上下文压缩都不用重做。你站在哪座建筑前、手里拿着什么，都会作为上下文自动附上；文件走现有的附件路径。
- **看**：雅典娜一边干活，一边说旁白。
- **定**：审批照旧弹出现有的原生审批窗口（它本来就是独立窗口），城里只同步显示这个状态：雅典娜停在门槛前，封印是红的。**网页永远不能发出"批准"**：页面里显示的文字有一部分是模型写的，一旦被注入脚本，就能替你点同意。
- **收**：结果变成实物交到你手上：报告是卷轴，表格是账册，图片是彩绘板，交付时带着颜色。长回答在游戏内的卷轴阅读器里读。对非技术用户来说，那段文字往往就是全部的答案，不能把人赶回对话模式去读。
- **评**：
  - 收下：颜色慢慢褪进城邦，成果成为历史的一部分（点开看时仍是原样）。
  - 退回：附一句意见，相当于在同一会话里追加一条修改要求。M1：退回只把"关于《…》，请修改："预填进同一会话的输入框并聚焦，由你写完发出——网页从不替人发消息，发消息仍只走输入框这一条路径。

  指着东西说"这里不对"，比用文字描述"上一份文件的第二段"容易得多。

### 7.2 城邦（几天到几周）

- **成果即藏品，摆在哪由你决定。** 图片挂进彩绘柱廊（古雅典真有一座专门挂画的柱廊），文档放进书库，表格收进金库。这就是沙盒：可以自由摆放，但摆的都是你自己的成果。藏品存在游戏存档里，不碰工作区，所以"拆方块"永远不会变成删文件。真要改文件，就变成一条交给雅典娜的委托，走正常的审批流程。
- **橄榄林。** 每完成一次委托，林中就长出一棵橄榄树（橄榄树是雅典娜送给雅典的礼物）。点一棵树，就选中那次会话。历史变成一片看得见的林子。
- **居民。** 第一次用到某项能力时，城里会多一位居民，比如抄写员、商人、传令官。以后去找他，就能知道这项能力还能做什么。

### 7.3 日常

- **委托板**：根据工作区现状，在本地生成三条具体建议，比如"下载区堆了 300 件东西，要不要整理"。它只读统计信息，不调用模型，解决的是非技术用户"不知道该让它干什么"的问题。
- **神谕**：在神庙设立"每日神谕"，背后就是建一个定时任务。默认设置下，定时任务本来就要用户亲自批准，所以这个仪式就是那次批准。之后每天早上，传令官会送来一卷。
- **传令官**：你回来时，他会播报离开期间发生的事：定时任务的结果、被打断的委托、外部改动（见第 10、11 节）。

### 7.4 看和玩并重

- 一个键就能在"镜头跟着你"和"镜头跟着雅典娜"之间切换。有东西轮到你时，屏幕边缘出现红色指示。
- 雅典娜干活不需要你盯着。只有交付和等待审批这两个时刻，镜头会轻轻建议你过去，但不强制。

## 8. 视觉语言

- **三条规则：**
  - 静止的世界是灰的；
  - **光**属于雅典娜，她在哪干活，哪里就亮；
  - **颜色**只给"轮到你了"的东西：待审批的请求、待查看的成果、她向你提的问题。同屏最多一到三处。
- **调子是"正午阳光下的大理石"，不是"黑白战争片"。** 《辛德勒的名单》的调子很沉重，照搬会让一个想留住人的游戏显得压抑。要的是高调光、柔和的阴影、通透的地中海空气。
- **点缀色建议用红绘陶器的赤陶红。** 它是希腊本身的颜色，又带着红衣女孩的联想。
- **兼顾色弱用户。** 红绿色弱在男性中相当常见（约 5%–8%），他们看红色和深灰差别不大。所以"轮到你了"必须同时有亮度对比，以及脉动或形状变化，不能只靠颜色本身。
- **写实靠光影和材质，不靠细节密度。** 2.5D 视角下人物本来就小，剪影和动作比贴图细节更重要。
- **人物不做 3D 近景。** 打样证实，代码生成的人物在游戏视距下读得出，近看就像一尊古典人体模特（脸、手、肘关节过不了关）。对话等特写改用 2D 半身像，默认风格是古希腊白底陶瓶那样的线描，用 SVG 画。

## 9. 工作区、会话与城邦

### 9.1 对应关系

- **一个工作区对应一座城邦。** 以 `WorkspaceProfile.Id`（GUID）为键，而不是路径。所以工作区改名不影响城邦；文件夹换了位置，只要重新定位（见 11.4），城邦和存档都还在。
- **"全局对话"对应雅典娜的神殿。** 没有工作区的会话（左侧的"全局对话"分组）没有文件可以生成城市，因此进入一个手工搭建的固定场景。它的所有文件操作都算"城外"。
- **多个工作区组成群岛。** 海图上每座岛是一座城邦，按工作区的创建时间排定位置，保持稳定；有会话在运行的岛会亮着灯。
- **一个会话对应一份委托。** 一座城邦里可以有许多份委托。雅典娜只有一位，她跟随当前选中的会话。

### 9.2 在游戏里切换

**左侧的会话树是唯一的选择来源。** 游戏不另存一份"当前会话"。游戏里的导航，比如点橄榄树、在海图上选岛、在委托板上开新委托，都调用同一条"选中会话"或"新建会话"的路径。这符合"避免状态重复"的约定，也保证两种模式看到的永远是同一个选择。

游戏模式下，在左侧点一个会话：

| 选中的会话位于 | 游戏里发生什么 |
|---|---|
| 同一个工作区 | 不换场景。雅典娜转向那份委托，出现在它最后一次动作的地点 |
| 另一个工作区 | 播放航海过场：出港 → 海上 → 靠岸，抵达那座城邦 |
| 全局对话 | 驶向神殿 |

- **切换会话不会把你踢回对话模式**，模式只由你手动切换。
- **沿用现有的"两拍"切换。** 第一拍（`OnSelectedConversationChanged`）只负责选中和出港。等 `ShellMaterial.RowSelectionSettle`（380 ms）过后，第二拍（`OnConversationSurfaceSwapDue`）才加载城邦。如果用方向键在树里一路按过去，计时器每次都会重启，只有停下来的那一次才加载城邦。
- **过场动画就是加载遮罩。** 时长取"最短观感时长"和"城邦就绪时间"中较长的一个，并设一个上限。超过上限就先靠岸，显示已经就绪的部分（顶层建筑），其余部分陆续出现。M1：最短 1.6 秒，上限 6 秒；城没有变（切走又切回）或装城失败时也要靠岸，不能卡在海上。
- **扫描在后台线程进行，范围有限、可以取消。** 新的切换会取消旧的扫描。
- **离开不会打断雅典娜干活。** 原城邦里的会话照样在后台运行（和对话模式一样），回来时，雅典娜的状态根据会话重新推导。
- **游戏模式下对话视图不可见，第二拍可以先不换气泡树，等切回对话时再换。** 这样在游戏里切换会话，就不会出现那 2–3 秒的冻结。工作台、终端等第二拍的其他工作照常进行。M1 实测：**只是隐藏消息列表没有用**——隐藏的列表换绑照样实体化整棵气泡树（可见 648 ms、隐藏 843 ms，都是 10 770 个视觉元素）。所以游戏模式下消息列表根本不给数据源，切回对话时升幕布、等一帧再给回去。

### 9.3 并发

- 同一城邦里有别的会话在运行（比如定时任务）时，它碰到的建筑窗口会亮灯，但不出现人物，以免分散对雅典娜的注意。
- 别的城邦有会话在运行时，海图上那座岛会亮灯；完成后，传令官来报。

## 10. 存档与重启

### 10.1 什么存，什么不存

原则：**能从文件或会话推导出来的不存**，存了就可能和真实情况不一致。

| 类别 | 内容 | 存不存 | 丢了会怎样 |
|---|---|---|---|
| 从文件推导 | 建筑、类型、体量、状态 | 不存，每次重算 | 无影响 |
| 从会话推导 | 雅典娜在做什么、橄榄林、哪些成果属于哪次委托 | 不存 | 无影响 |
| 布局账本 | 每个文件夹占哪块地、已删文件夹留下的空地、网格的生长顺序 | **存** | 城市重排，空间记忆作废 |
| 藏品与沙盒 | 摆放的成果及其位置、指向的文件（相对路径 + 内容指纹 + 来源消息 Id）、每件成果是收下还是退回 | **存，最重要** | 用户亲手摆放的东西丢失，这是唯一无法恢复的部分 |
| 玩家进度 | 在每座城邦里的位置和镜头、已结识的居民 | 存 | 回到广场；居民可以从会话归档重新推导 |
| 索引快照 | 每座建筑的汇总（各类文件数量、最后修改时间、总大小），以及藏品所指文件的指纹 | 存（作缓存） | 少一次"离开期间的变化"报告，下次重建 |
| 全局 | 当前模式（对话/游戏）、上次选中的会话 | 存 | 回到默认状态 |

动画进度、雅典娜走到半路的位置这类瞬时状态都不存。

### 10.2 存在哪，怎么写

- **每座城邦**的存档放在 `AthenaData/Workspaces/<workspaceId>/game/`。这个按工作区划分的目录已经存在（目前放着 `knowledge/`），删除工作区时 `WorkspaceService` 会把整个目录删掉。所以游戏存档的生命周期跟工作区一致：删工作区时一起删，重新定位时一起保留。目录下有两个文件：
  - `polis.json`：布局账本、藏品与沙盒、玩家进度；
  - `index.json`：索引快照，纯缓存，删了也不会出错。
- **神殿**的存档：`AthenaData/Game/sanctuary.json`。
- **全局**：当前模式写进 `MainLayoutSettings`（和 `RightPanelCollapsed` 是同一类设置）；上次选中的会话另外保存。
- **写入方式照搬 `CronTaskStore` / `PetProfileStore`：**
  - 先写临时文件，再原子替换；
  - 按记录隔离损坏，一件藏品的记录坏了不能连累整座城；
  - 保留上一份完好的副本；
  - 带 schema 版本号，加载时迁移。

### 10.3 重启之后

1. **模式**：上次停在游戏模式，就直接进入游戏。
2. **城邦**：回到上次选中的会话所在的城邦。现在启动时选中的是**最近更新**的会话（见 `MainWindowViewModel.InitializeConversationTreeAsync`），夜里只要跑过一次定时任务，就会把你带到那个任务所在的城邦。建议改为保存上次选中的会话，找不到时再退回最近更新的会话。这个改动对对话模式同样适用。
3. **先显示，再核对**：先按索引快照把城邦画出来，让画面立刻可见；然后在后台扫描，算出差异，再由传令官播报离开期间的变化。
4. **雅典娜**：站在她上次干活的地方（根据该会话最后一次工具调用的目标推导）；推导不出来就站在广场。
5. **被打断的委托**：退出时还在运行的会话会被标为中断（`WasInterrupted`）。在城里，它表现为停工的脚手架，雅典娜会问你要不要继续；你确认后，就发出一条"继续"。
6. **离开期间的定时任务**：结果由传令官送来，带着颜色等你查看。
7. **未处理的成果**：重启前既没收下也没退回的，仍然带着颜色在原地等你。收下或退回的状态本身就是存档的一部分。

## 11. 应用外的改动

### 11.1 原则

文件系统是唯一的事实来源。**文件监听只是提示，扫描结果才算数**，因为监听可能丢事件，扫描不会。

### 11.2 应用开着，你就在这座城邦里

- **只监听当前城邦，并且和工作台共用同一个监听。** 工作台的 `WorkspaceWorkbenchViewModel.StartWatcher` 已经在监听当前工作区（包含子目录，去抖 250 ms）。把它提成一个服务，让工作台和游戏都订阅它，不要再开第二个递归监听。
- **增量更新**：只重算受影响建筑的汇总。新建的文件夹在城市边缘起一座建筑；删除的留下空地；文件增减让建筑的体量和状态逐渐变化。
- **区分是谁改的**：把变化的路径和本回合工具调用的目标对比。
  - 对得上，就是雅典娜改的：她的动作已经演过，不再重复。
  - 对不上，就是外部改动：不配角色动作，只让建筑轻微变化，并记到广场的公告板上。

  这样"光属于雅典娜"这条规则就不会撒谎：外部改动没有光。
- **一大批改动**：`git checkout`、解压一个包这类成百上千个文件的变化，按建筑合并；超过阈值，就只播一次"城里起了大变化"，然后整体重新扫描。M1：一批里超过 200 处改动、或者涉及 8 座以上建筑，就整城重扫；否则只重扫受影响的顶层文件夹。
- **监听出错**：Windows 上的缓冲区溢出、Linux 上的 inotify 数量上限，都可能让监听丢事件或根本建不起来。现在工作台的监听没有订阅 `Error` 事件，事件丢了也没人知道。游戏要求补上这一点：出错时整城重扫；监听建不起来时，退化为"每次回到游戏时重扫"，并提示用户。
- **改名**：运行时能收到改名事件。建筑原地换牌匾，藏品的引用跟着改。
- **文件内容被改**（比如在 Word 里改了一份报告）：对应的物品挂上"刚被修改"的标记。查找藏品时先按路径找；路径还在，就保持关联并更新指纹。

### 11.3 应用关着，或你在别的城邦

这两种情况用同一个机制处理：回到城邦时，把索引快照和一次新的扫描做对比，得到差异。

- 差异合并成一份"你离开期间"的报告，由传令官播报。建筑一次到位，不逐个播放动画。
- 离线期间的改名没法直接知道，只能推断：
  - 文件夹按子项名称集合的相似度配对（M1：Jaccard ≥ 0.5、一对一，没有子项的文件夹不配；认错的代价是把牌匾挂错，认不出只是多一块空地）；
  - 藏品按内容指纹（大小 + 哈希）在同一座城邦里找回。

  都找不到的标为"遗失"：保留记录和名字，显示为空底座，由你决定是否移除，绝不自动删除。

### 11.4 文件夹本身不见了

工作区文件夹被移动或删除后，`SetWorkspaceAsync` 现在会直接返回，工作台显示为空。

在游戏里，这座城邦显示为笼罩在雾中，提示"找不到这座城邦的文件夹"，并提供"重新定位"：只改 `DirectoryPath`，`Id` 不变，存档全部保留。

这是一个**新功能**。现在没有重新定位的入口；重新添加文件夹会得到一个新的 `Id`，也就是一座新城邦，旧存档就断了。

## 12. 技术架构

### 12.1 承载

- 游戏页面运行在 `Avalonia.Controls.WebView` 的 `NativeWebView` 里。页面和资源由现有的本地回环服务（`Services/Preview/OfficePreviewHost.cs`）新增一条路由来提供，离线打包沿用 `Tools/PreviewVendor` 的做法。
- 位置在中间区域：标题栏放一个切换按钮（和右栏折叠按钮在同一处），游戏视图替换消息列表所在的那一行，输入框保留在下方。
- 进入游戏模式时要把宠物收起来。宠物是窗口级的覆盖层（`Views/MainWindow.axaml` 里 `ZIndex` 为 60 的 `VirtualPetView`），会被原生 WebView 盖住。

### 12.2 渲染

- **用实时 3D 加正交相机，不用预渲染的精灵图。** 理由有三：
  - 骨骼动画天然一致。绑好骨骼的模型配上动作捕捉，长不出多余的翅膀；猫头鹰的问题恰恰出在逐帧生成。
  - 红衣女孩效果就是一个后期着色器：除了打了标记的物体，其余全部去色。
  - 黑白灰对写实风格是条捷径。来源不同的素材，去色、调好对比度后很容易统一；灰盒原型看起来也离最终画面不远。
- **引擎以 three.js 为基线。** v1 原本倾向 Babylon.js（胶片感需要的颗粒、泛光、暗角、调色都在它的默认渲染管线里，导航网格也有现成插件）。但打样用仓库里现成的 three.js 0.185 已经实现了这套画风：正交相机、GTAO、软阴影、按遮罩去色的后期都顺利跑通（见 12.8）。M0 定引擎时以 three.js 为基线；要换 Babylon.js，需要说清它多给了什么。
- **屏幕空间效果必须用当帧的相机矩阵投影。** 雅典娜的光晕、跟随人物的标注都属于这一类。three.js 的 `lookAt`（OrbitControls 每帧都会调用）会先用"新位置 + 旧朝向"刷新相机矩阵，直到渲染时才改正。在渲染前投影而不先更新矩阵，效果就会在镜头运动时滑开、停下才归位（打样里实测偏差 170 / 538 / 2903 像素）。

### 12.3 通道与事件来源

- **C# → 网页**：用 `InvokeScript`。每次调用都是一次异步往返，所以事件要攒成批再推送（约 100 ms 一批），推理增量也不逐字推送。
- **网页 → C#**：用 `WebMessageReceived`，只接受固定的几种意图，C# 逐条校验。
- **事件来源**：从气泡已经在用的渲染模型里推导，包括 `ChatMessage.Segments`、`ToolCallEntry.Status`、审批队列状态、子代理快照。推导放在 ViewModel 层，和气泡属于同一种呈现。不要再给 `IChatService.StreamMessageAsync` 加回调，它已经有 11 个了。
- **分工**：C# 负责扫描、建筑汇总、布局账本和差异计算，这些都是纯函数，可以放进 `Athena.Archive.Tests` 测试。网页只负责把地块、建筑、人物画出来，并编排动画。

### 12.4 安全边界

- 网页发回的意图是一个封闭集合：选中会话、新建委托、打开文件、把文件作为附件、预填输入框、停止当前回合。每一条都在 C# 端校验，路径必须落在当前工作区内。
- **审批不进网页**：网页没有"批准"这种意图。
- C# 发给网页的只有事件类型和工作区相对路径（或"城外"），不带文件内容和工具输出。唯一的例外是卷轴阅读器：你点"读"一件回答类成果时，那段回答的 Markdown 按需发给页面（它本来就是交给你的东西）。
- 文件名和 Agent 写的文字一律画在 canvas 上，不放进 innerHTML。否则，一个名叫 `<img onerror=…>` 的文件，会在一个能调用 C# 的页面里变成可执行的脚本。卷轴阅读器渲染 Markdown 时要禁用原始 HTML，页面还要加上内容安全策略（CSP）。

### 12.5 失败处理（含 Linux）

Linux 和其他平台走同一套流程。失败在四个地方检测：

1. WebView 创建或挂载失败：沿用 Office 预览中 `OfficePreviewBridge.HandleAttachFailure` 的处理方式；
2. 页面加载失败（`NavigationCompleted` 报告失败）；
3. 页面自检发现 WebGL 不可用，回传给 C#；
4. 页面迟迟不报"就绪"，按超时处理（M1：从创建页面起 20 秒——导航本身卡住也算超时）。

任何一处触发，都要在游戏区域显示原因（附上技术细节，方便反馈）和"回到对话"按钮，并写一条 Warning 日志。不要悄悄退回对话模式。

### 12.6 性能

- 切到对话模式或窗口最小化时，暂停渲染；空闲时降低帧率（例如 30 帧）。
- 切回对话后，WebView 保留一段时间再释放，免得来回切换时重新加载场景（M1：3 分钟）。

### 12.7 测试

- 网页侧的纯逻辑（动作编排、合并、限制滞后）用 Node 写单元测试。
- 页面冒烟测试用 Playwright（已在依赖里），分别跑 Chromium 和 WebKit，大致对应 WebView2 和 WKWebView。
- C# 侧的扫描汇总、布局账本、差异计算、事件推导、意图校验，放进 `Athena.Archive.Tests`。
- 无头测试套件只验证模式切换和失败提示，不创建 WebView 实例（和 Office 预览的惰性创建是同一做法）。
- **运动自检是验收的一部分。** 静止截图查不出只在运动中出现的缺陷：镜头不动时，屏幕空间效果的位置和真实投影永远一致。做法是用脚本让镜头逐帧移动，比较效果每帧用的位置与当帧的真实投影，最大偏差应为 0。打样里的 `?selftest=glow` 就是这个形状，修复前后各跑一次。
- **截图和视觉审查**：用应用自带的 Playwright 驱动驱动本机 Chrome 截图（打样的 `shoot.mjs`），GPU 渲染，一张约 0.6 秒。不要用系统 Chrome 的 `--headless --screenshot`：它在 macOS 上拿不到显示链路，会一直等一帧而挂死。

### 12.8 美术打样（2026-10-11）

`Artwork/Polis/sample/` 是一个完全由代码生成的场景（约 820 行 JS，没有任何外部素材），用来回答"代码能把美术做到什么程度"。用法见文件头的注释。

| 项 | 结论 |
|---|---|
| 建筑 | 立得住。多立克神庙按古典比例生成：收分、带凹槽的柱身，柱头，转角处的三陇板檐壁，山花，瓦垄和瓦当，顶饰，三级台基 |
| 器物 | 很好。双耳瓶带黑绘的回纹和放射纹；满屏灰里只有那只红陶瓶有颜色，"轮到你了"的规则在实际画面里成立 |
| 植物与地面 | 过得去。柏树、干土、条石铺地可用，橄榄树冠还有点像花椰菜 |
| 光与调色 | 第 8 节的规则都兑现了：高调光、环境光遮蔽、软阴影、黑白调色、只给标记物体留色、光晕只绕在雅典娜的轮廓外 |
| 人物 | 游戏视距（约 50 像素高）和中景（约 130 像素）下读得出是一位穿佩普洛斯、周身有光的女子；近看是古典人体模特，所以定下了"人物不做 3D 近景"（第 1、8 节） |

打样中发现并修掉的三个问题，各自变成了一条要求：

1. **远处地面出现黑色斜带**：噪声周期超出格点表，越界读出 NaN，整排像素变黑。→ 程序化生成器的参数越界要直接报错，不能静默地生成坏数据。
2. **点缀色悄悄失效**：`ShaderPass` 构造时会克隆 uniforms，渲染目标的贴图不能被克隆，被置成了空。→ 遮罩这类渲染目标贴图要在构造之后再挂上。
3. **光晕在镜头运动时漂移**：原因见 12.2。这个问题是用户拖动镜头时先发现的，三张静止截图都没暴露。→ 运动自检（12.7）。

## 13. 风险

- **人物近景是代码美术的上限。** 建筑、器物、环境和光影已经在打样里验证可行；人物在游戏视距下可用，近看不行。所以人物近景交给 2D 半身像。代码美术剩下的成本主要在数量和审查上：几十件资产要风格统一，每一件都要看过。
- **静止画面查不出运动中的缺陷。** 光晕漂移就是例子。凡是屏幕空间效果、动画、镜头跟随，都必须过运动自检（12.7）。
- **新鲜感会过去。** 好看只能撑几天，真正留住人的是积累和每天的实际用处。
- **游戏比对话慢。** 原则 2 就是为此定的，但必须实测。
- **原生 WebView 永远在最上层。** Avalonia 的内容画不到它上面，任何想叠在游戏画面上的界面都要另想办法（独立弹窗不受影响）。

## 14. 里程碑
