# 桌面性能专项

## 测量条件

2026-11-27，Apple M4、24 GB 内存、macOS 27.3、60 Hz 显示器，.NET SDK 10.0.101。对照版本是提交 `3d936ab`。两版都使用原生 macOS 窗口、同一显示器、相同夹具和发布版自包含程序。新版 RID 发布启用 ReadyToRun，保留 IL。本机应用发布目录从 197 MiB 增至 268 MiB，体积统计范围不含更新器和 Electron。

夹具每次重建 100 份原有 SQLite 表结构的归档。最近两份归档各有 160 轮，每份包含 1,000 条存档消息、320 条用户可见消息和 640 次工具调用。每份有 4 段 26,254 至 26,255 字符的正文、8 张 Mermaid 流程图、16 处 1,254 × 1,254 PNG 和 16 处 WAV，包含表格、链接、任务列表、公式、代码和推理分段。相同媒体内容复用本地文件，每处使用自己的附件 ID。其余 98 份各有 10 轮。另设一个含 2,400 个候选项的供应商及 400 条本地参考模型记录。

启动由父进程在启动应用前计时。结束条件包括选中目标会话、加载遮罩已消失、滚动位于底部、末条回复在视口内具有实际尺寸、图片解码完成、Markdown 代码、Mermaid、工具过程和音频文件名控件均有实际尺寸，并收到渲染线程确认。切换计时包含原有的 380 毫秒选中动画。每次退出旧进程，每次重新建立归档目录索引。会话和配置均在临时目录，检查项目不会读取日常使用的聊天内容。

滚动和拖栏各持续约 3 秒。鼠标经过 Avalonia 原生窗口的输入后端，使用正常的命中测试、捕获和滚轮事件。长会话在末尾及首次到达第 81 轮时分别往返滚动，每个方向每帧输入两格滚轮。两侧拖动时持续测量会话区域的实际宽度，同时检查 `ShowsPreview=false`，拖动方向按当时的列宽选择，覆盖约 96 个逻辑像素。下拉框在悬停指针下滚动。帧率按渲染线程已完成且几何确实变化的独立批次除以整段耗时计算，重复批次合并，原始数据保留每轮帧数、移动距离、P95 和最大帧间隔。本机达标线为 57 帧/秒。这里测量到合成器提交完成，物理面板扫描输出和操作系统磁盘缓存清空均未测量。

## 原生实测

旧版本运行一轮。下表新版来自同一已使用过的发布程序，连续五次完全退出并重新启动，每轮重新生成 100 份归档，所有数值列出最小值和最大值。每一次、每一个手势均通过对应门槛。首轮经新的临时路径启动，并保留已安装程序文件的身份。[逐轮 JSON、帧间隔和移动距离](../Tools/DesktopPerformance/results/macos-arm64-60hz.json)

| 操作 | 旧版 | 新版五轮 |
| --- | ---: | ---: |
| 冷启动至选中会话末条富消息可读 | 9.737 秒 | 1.619–1.959 秒 |
| 切换至另一超大会话 | 13.030 秒 | 0.676–0.699 秒 |
| 切换就绪时已构建的消息行 | 1,000 | 9 |
| 定位到第 81 轮 | 24 毫秒 | 207–227 毫秒 |
| 会话末尾往返滚动 | 59.64 FPS | 58.74–59.98 FPS |
| 会话中段首次往返滚动 | 58.86 FPS | 59.05–59.58 FPS |
| 左栏实时拖动 | 2.30 FPS | 59.01–59.67 FPS |
| 右栏实时拖动 | 1.11 FPS | 59.80–60.14 FPS |
| 打开供应商模型页面 | 19,223 毫秒 | 63–68 毫秒 |
| 展开 2,400 项模型下拉框 | 608 毫秒 | 31–35 毫秒 |
| 滚动模型选项 | 25.27 FPS | 58.73–59.48 FPS |

五轮中，聊天与拖栏的最慢单帧间隔为 36.8 毫秒，模型下拉为 53.7 毫秒。中段定位时才构建周围的气泡，因而单次定位比已经预先构建全部消息的原版多用约 0.2 秒。拖栏时本轮测得的会话宽度实际变化为左侧 95、右侧 96 个逻辑像素。

另在三份隔离的 macOS 安装中，先启动旧版并实际打开选中的富消息，然后让正式更新器覆盖安装、保留同一份 100 会话数据库并启动新版。由操作系统报告的新进程创建时间计至富消息可读，原更新器为 2.218–2.263 秒，优化后的更新器为 **1.810–1.824 秒**。从启动优化后的更新器到新版就绪共 2.070–3.882 秒，含本机文件安装，不含下载。新旧应用 302 个顶层文件中有 201 个内容和权限相同，合计约 104 MiB。

同一二进制刚发布时的首次打开单独计为 5.687 秒，其后四次为 1.623–1.645 秒。重新复制全部顶层程序文件后首次打开为 3.645 秒，超过 3 秒目标。父进程启动到程序写入首条启动日志的时间分别为 2.238 秒和 0.840 秒。同机额外比较了单文件 ReadyToRun 和关闭 ReadyToRun 的多文件发布，新文件首次启动分别为 5.742 和 6.152 秒。专项保留自包含多文件 ReadyToRun 发布。这些额外样本也保存在逐轮 JSON 中。

## 实现与回归范围

| 路径 | 修改与验证重点 |
| --- | --- |
| 启动、历史树与搜索 | SQLite 覆盖索引读取目录，启动期间并行准备最初的消息正文，打开会话才构建其模型。磁盘全文检索使用原有的 Unicode 大小写匹配语义，实时编辑的会话使用内存内容。回归覆盖连续选择、关闭时保存、未打开归档的正文完整性、重命名和置顶。 |
| 消息滚动、切换与缩放 | 消息保持独立的实测行高。视口按像素定位，保留最近访问的有限数量气泡，按视口距离在帧间逐个准备相邻的原生 Markdown。纯文字段落让不同宽度的换行复用已塑形的字形，特殊行间距和选区由原生控件处理。回归对比中英阿拉伯文在四种宽度与字号变化时每一行的长度、高度及选择内容。视口外的估计边界不参加绘制和命中测试。附图解码随气泡挂载和释放，协议载体保留在完整历史中。原生输入定位到 Mermaid 图曾吞掉整段滚轮，普通滚轮现在交由聊天滚动容器处理，Ctrl 或 ⌘ 加滚轮仍可缩放图表。回归覆盖滚动锚点、可见性切换、键盘首尾跳转、追加、截断和释放。 |
| 供应商与模型 | 同一份参考目录只建立一次确定性匹配索引。能力筛选只运行可能授予能力的匹配规则，详情仍可取完整的模糊建议。角色缓存候选列表，供应商、模型集合和元数据变更时使对应缓存失效。打开页面按需解析行详情。刷新时一次发布全部模型，配置保存一并跟踪新的集合。保留搜索、手动绑定、歧义和过期模型的处理。 |
| 知识库、向量与 FTS | 文件树在工作线程构建，一次发布最新结果。混合检索复用同一索引快照的片段字典。SQLite 批量写入复用参数和命令，文件、词项及向量仍在同一事务提交。 |
| 日志、工作区与 Office | 后台查询日志，合并同时到达的日志通知，丢弃过时查询。工作区差异列表一次提交。XLSX 检查在遍历时累计公式、错误、最大行列及预览，保留原有输出。 |
| 对话和桌面组件 | 流式追加只更新新消息的操作状态。草稿变化签名采用流式 SHA-256 并兼容旧签名。按所选语言载入资源字典并缓存，日常文案跳过转义扫描。主题图像按需解码，历史气泡按需创建语音、生成和压缩状态控件。上下文检查器首次打开时构建并保留视图，猫头鹰弹层关闭时卸载并停止自身动画时钟。关闭的桌宠跳过内置图集解码与视图时钟。 |
| macOS 更新器 | 更新前比较常规文件的长度、权限、属性和分块内容。相同文件保留原有文件及修改时间，有变化的文件仍从暂存包覆盖安装。回归包含同长度、同时间戳且仅末尾字节不同的文件，以及只有执行权限不同的文件。 |
| 其余路径 | 核查了会话压缩及工具协议、执行时间线、计划任务、子代理、浏览器、音频、其余 Office 路径的入口和调用关系。定量帧率针对上面的桌面交互。功能测试覆盖面按仓库套件报告。游戏模式未作专项修改。 |

## 复现

准备本仓库的 .NET 10 和 PTC 本地包源，在有显示器的桌面会话中从仓库根目录运行。

```sh
python3 Scripts/benchmark-desktop.py --runs 5 --report /tmp/athena-desktop.json
```

已发布的目录可用 `--app-dir` 指定。观察器构建后可加 `--no-build`。macOS 默认读取主显示器刷新率，其他环境或跨屏测试用 `--hz` 指定窗口所在屏幕的刷新率。单测冷启动可以加 `--startup-only`。全新文件副本的首次打开使用 `--fresh-install`，对照旧版使用 `--baseline` 保留原始测量。常规模式逐次检查启动和切换均小于 3 秒，以及两处聊天滚动、两侧实时拖动和模型下拉滚动均达到刷新率的 95%。

```sh
dotnet build Athena.UI.sln -c Release -p:UseAppHost=false
dotnet Athena.Archive.Tests/bin/Release/net10.0/Athena.Archive.Tests.dll
dotnet Athena.Presentation.Tests/bin/Release/net10.0/Athena.Presentation.Tests.dll
bash Scripts/run-headless-tests.sh /tmp/athena-ui/main.png
```

真实更新与重新启动可用下列命令复现。两个应用路径分别指向旧版和新版的自包含发布目录。更新器和应用均使用临时安装副本，更新器按实际流程重启新版。

```sh
python3 Scripts/benchmark-desktop-update.py --previous /path/to/previous-publish --app-dir /path/to/new-publish --updater /path/to/updater/Athena.Updater --runs 3 --report /tmp/athena-update.json
```

macOS 的无头套件会验证实际工作区路径和文件访问边界，本次为它单独指定用户缓存目录下的 `TMPDIR`。归档套件使用系统默认临时目录。原生性能测试单独运行。

完整无头 UI 套件有 174 条通过记录，归档套件有 211 条，Presentation 往返与损坏检查全部通过。PTC 的 Core 58 项、JavaScript 38 项通过。无头套件覆盖原有游戏生命周期，专项没有修改游戏模式源码。

Release 解决方案在本机构建成功。应用与更新器分别通过 macOS arm64、Windows x64 和 Linux x64 自包含发布检查。Windows 与 Linux 的交互帧率尚无实机数据。
